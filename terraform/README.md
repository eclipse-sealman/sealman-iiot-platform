# Azure Prerequisites (Terraform)

Provisions the Azure resources the platform needs before `docker compose up`, and
renders the six Azure variables for your `.env` file.

This automates the manual steps in
[../docs/prerequisites/iot-hub.md](../docs/prerequisites/iot-hub.md) and
[../docs/prerequisites/storage-account.md](../docs/prerequisites/storage-account.md).

## What gets created

| Resource | Purpose |
| --- | --- |
| Resource group | Holds everything below |
| IoT Hub (`S1` by default) | Device registry and deployments |
| Shared access policy | `RegistryRead/Write`, `ServiceConnect`, `DeviceConnect` — signs `SAS_TOKEN` |
| Public storage account | Container `iotedge-device-twin`, device-facing module twin config |
| Internal storage account | Container `platform-config`, platform settings |
| 3 seed blobs | `services.json`, `endpoint-types.json`, `templates.json` |

Both containers are **private**; access is via the generated SAS tokens.

## Prerequisites

- Terraform >= 1.5 and Python 3 (standard library only)
- Azure CLI, logged in: `az login`
- Permission to create resource groups, IoT Hubs and storage accounts

## Usage

```shell
cd terraform

# optional: override defaults (region, names, SKU, ...)
cp terraform.tfvars.example terraform.tfvars

terraform init
terraform apply

# render the Azure variables
python3 scripts/gen-env.py
```

`gen-env.py` writes `../.env.azure` (mode `0600`, gitignored). Copy those six
values into your `.env`, then start the platform:

```shell
docker compose up --pull always
```

Use `--stdout` to print instead of writing a file, and `--ttl-days N` to set the
IoT Hub token lifetime (default 30).

## Refreshing an expired SAS token

IoT Hub SAS tokens expire. When the API starts failing to authenticate against
Azure, mint a new one — no Azure call, no Terraform apply:

```shell
python3 terraform/scripts/gen-env.py --ttl-days 30
```

The **blob** SAS tokens are issued by Terraform and last `sas_validity_days`
(default 90). After that window, `terraform apply` reissues them.

## Notable variables

| Variable | Default | Notes |
| --- | --- | --- |
| `location` | `westeurope` | Any region supporting IoT Hub |
| `name_prefix` | `sealman` | Prefixes resource names; a random 4-char suffix keeps storage account names globally unique |
| `iothub_sku` | `S1` | The platform requires a Standard tier. `F1` is free but limited to one per subscription |
| `use_single_storage_account` | `false` | `true` puts both containers in one account — cheaper for local dev, drops the public/internal split |
| `sas_validity_days` | `90` | Lifetime of the blob SAS tokens |

## Design notes

- **The IoT Hub SAS token is not generated by Terraform.** Terraform has no
  HMAC-SHA256 function and the azurerm provider exposes only the policy key, so
  `scripts/gen-env.py` signs the token. This also means expiry is handled by
  re-running one script instead of re-applying infrastructure.
- **SAS validity is anchored to a `time_rotating` resource**, not `timestamp()`,
  which would make the SAS data sources dirty on every plan.
- **Seed blob content changes are ignored** (`lifecycle.ignore_changes`) so the
  platform's own writes to `services.json` and friends survive the next apply.
- `IOT_HUB_NAME` is the IoT Hub **host name** (`…azure-devices.net`), not the
  bare resource name — a common source of confusion.
- Terraform does **not** create the `seal-base-deployment` IoT Hub deployment;
  the API bootstraps that on first start (`BOOTSTRAP_IOTHUB_DEPLOYMENT_NAME`).

## State and secrets

State is **local** by default (`terraform.tfstate`) and contains storage account
keys and SAS tokens in plaintext. It is gitignored, along with `.env.azure` and
`*.tfvars`. For shared environments, uncomment the `azurerm` backend in
`versions.tf` and run `terraform init -migrate-state`.

## Teardown

```shell
terraform destroy
```
